# Production-хостинг: доступ из России и из-за рубежа
Дата решения: 29.10.2026. Статус: архитектурное требование; НЕ означает, что production развернут или доступность проверена.

## Цели и ограничения
1. Гостевой сайт, приватная админка, RSVP, персональные страницы и фото работают **без VPN** как из России, так и из зарубежных стран, где проживают приглашённые. Нельзя автоматически считать российский хостинг доступным за границей.
2. Имена, фотографии, связи, RSVP, персональные истории, заметки, договоры и бюджет не попадут в публичный GitHub, GitHub Pages, статический JSON или журналы веб-сервера.
3. Единственная основная база данных размещается в российском ЦОД; резервные копии и приватное файловое хранилище — там же. При обработке персональных данных требуется определить законные основания, согласия и правила доступа.
4. Рабочий сайт не должен зависеть от GitHub, Supabase Cloud, зарубежных CDN, API, шрифтов и хостов иллюстраций. Внешние изображения в демопрототипе подлежат удалению/замене локальными разрешёнными файлами.
5. При недоступности интернета по любому пути данные нельзя терять: формы показывают понятную ошибку и предлагают повторить отправку, не подтверждают RSVP до успешной записи.

## Предпочтительная минимальная конфигурация (предварительно)
- Timeweb Cloud, российская зона Санкт-Петербурга, например SPB-3 (проверить зону и точный регион при заказе).
- Node.js API + frontend + HTTPS на VPS в РФ, приватный PostgreSQL (локальный на VPS для MVP, либо managed PostgreSQL SPB-3 при необходимости), приватное S3 в Санкт-Петербурге.
- Собственный домен, автопродление TLS, локальное хранение CSS/JS/шрифтов/изображений и понятные адреса.
- Хостинг/провайдер может быть заменён после реального теста доступности с российских и международных сетей. Международная связность Timeweb (в PeeringDB помечена Global) НЕ равна гарантии доступности для всех стран.
- Сохраняем GitHub только как репозиторий кода; посетители не обращаются к нему на работающем сайте.

## Обязательная проверка до начала приглашений
1. На **реальном production-домене и IP**, на созданном в РФ сервере выполнить независимые внешние проверки HTTP(S), DNS, TLS, API, загрузки изображений, отправки/получения RSVP и загрузки фотографии.
2. География: минимум РФ (СПб, Москва, мобильный провайдер), Германия, Австрия, Великобритания, США, Нидерланды; добавить фактические страны гостей по мере заполнения адресов.
3. Проверять **с реальных сетей/внешних узлов**, а не только географию на VPN одного компьютера; отдельно IPv4/IPv6 (если включён), разные браузеры и смартфоны. При ошибках 403/451/5xx, DNS failure, блокировках WAF — исправить до запуска.
4. Проверить не только главную, но и авторизованный вход, страницы гостей, фото, RSVP. Зафиксировать время ответа, HTTP-статусы и дату проверки; включить регулярный мониторинг минимум из РФ, ЕС и США.
5. Прогнать отказоустойчивость: резервное копирование и восстановление, истечение токена, неавторизованный доступ, лимиты загрузок, повторная отправка RSVP.

## Решение при проблемах международного доступа
- Сначала диагностировать DNS, конкретный IP/ASN, WAF/geo ACL, TLS и международную маршрутизацию, сравнить Timeweb с альтернативными российскими провайдерами, например Selectel/Yandex Cloud.
- Не включать запрещающие доступ по странам правила и не навязывать CAPTCHA или SMS провайдеров, недоступных иностранцам.
- Опционально раздавать только **публичные статические материалы** через независимый международный зеркальный узел; персональная база остаётся в РФ и публикуется только после авторизации. Зеркало — не обязательный пункт и тоже требует отдельных тестов доступности в РФ.
- Публиковать приглашения только когда международный сценарий проверен и задокументирован.

## Исходное состояние
Сейчас есть публичный демонстрационный фронтенд и Supabase-ориентированная черновая миграция, но **нет ни российской production-инфраструктуры, ни защищённой онлайн-базы, ни подтверждённых результатов международного тестирования**.

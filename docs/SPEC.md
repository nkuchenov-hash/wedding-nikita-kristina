## Три уровня
1. **Публичная часть**: лендинг, программа, организационная информация, адреса, общая информация о празднике.
2. **Пространство приглашённых**: список гостей (с учётом согласия на публикацию), индивидуальные страницы гостей с городом, связью с парой, рассказом, фотографиями; RSVP и загрузка фотографий без обычной регистрации с паролем. Способ подтверждения права редактирования ещё предстоит выбрать.
3. **Админка Никиты и Кристины**: вся организационная работа, бюджеты, переговоры, документы, частные данные и управление гостевыми разделами. Защищённый вход обязателен до добавления реальных данных.

## Списки гостей, профили и сопровождающие (уточнение 29.10.2026)
- **Единый источник данных**: у каждого человека одна запись, используемая для админки, RSVP, списка приглашённых и разрешённой к показу персональной страницы.
- Профиль хранит имя/фамилию, сторону пары, группу знакомства (семья, школа, вуз и др.), связи с другими гостями, фотографии, историю знакомства/отношений с парой и отдельные приватные заметки; публичность каждого поля контролируется.
- Статусы **обсуждается / решили пригласить / приглашён / подтвердил / отказался** должны быть различимы. Предварительное упоминание в черновом списке не означает отправленного приглашения.
- **У любого гостя, не состоящего в уже внесённой паре, организаторы могут разрешить «+1»** независимо от группы знакомства; по умолчанию это не автоматическое приглашение. Для каждого приглашения — отдельное поле «можно взять сопровождающего», выбранный лимит (обычно 1), имя сопровождающего (необязательно до RSVP), ответ и статус. Возможность включить/убрать «+1» в админке для любого гостя.
- Уже именованные пары/семьи связываются между собой, чтобы «+1» не дублировал существующего гостя. Дети — отдельные связанные записи, количество неизвестных детей не выдумывать.
- Сводка по численности отдельно показывает черновой список, потенциальных безымянных «+1», отправленные приглашения и подтверждённых участников; не включать потенциальный «+1» в подтверждённое число.
- Списки и персональные истории нельзя показывать в публичной демоверсии до настройки серверной авторизации, контроля доступа и согласия на публикацию.
